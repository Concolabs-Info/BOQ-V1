## Candidate → measured object flow

```text
Raw AI JSON
    ↓
RoofDetectionCandidate
    ↓ validation/normalization
Confirmed/Editable Roof Domain Objects
    ↓ deterministic rules
MeasuredWorkObject(s)
    ↓
Workbook / BOQ
```

Do not make AI JSON the database model.

## Geometry storage

Store canonical geometry in source-image/project coordinate form plus transforms.

Recommended:

- original source pixel geometry for audit/re-render
- normalized internal geometry/transform for cross-drawing alignment
- real-world measured values generated by measurement service

## Services

Suggested backend services:

- `RoofInputResolver`
- `RoofPreprocessor`
- `RoofAiDetector`
- `RoofDetectionValidator`
- `RoofRepairService`
- `RoofGeometryService`
- `RoofPitchResolver`
- `RoofEvidenceResolver`
- `RoofSystemResolver`
- `RoofMeasurementService`
- `RoofDerivedMaterialService`
- `RoofNrm2Mapper`
- `RoofVersionService`

Keep services small and testable.

## Jobs

Long-running operations should be jobs:

- preprocess roof source
- primary roof detection
- targeted repair
- system/schedule extraction when needed
- recompute measured quantities

User edits should usually recalculate synchronously or through a short deterministic job, not call AI.
